vue input dom未更新trim值

遇到一个 vue 的问题，封装组件的时候，通过 defineModel 这个宏去操作外部绑定的 trim 修饰符（实现封装的组件可以在外部写 v-model.trim 时直接去除绑定变量的前后空格）时的处理函数，第一次修改以后会更新正确的 trim 函数，但是第一次 trim 后再次输入时只输入空格，会不进行任何操作，并且失焦或者回车后视图不更新。
打印 input 事件发现 dom 的 target.value 未更新 trim 操作的值，但是外部的变量是正确 trim 后的

打印 input 原生框输入值，set 函数接收值，modelValue 外部绑定值

发现其实通过打印变量，最终数据更新了也是正确的，但没更新视图，解决方法是 input 框监听 change 事件，并传入 event，在 evnet 中判断 modelModifiers 是否带 trim 修饰符，nextTick 更新视图后用传入的最新值更新一下 dom 的 target.value，让 dom 的值改变


或者设置一个 key，change 的时候，去 math.random 一个值去强制重新渲染一下这这个 dom

defineModel 通过 Playground 编译后，发现使用的主要是 useModel 这一方法，


是使用 customRef 去实现的，trim 以后，他有一个 hasChanged 函数去作对比，其实 trim 后他的内容是没变的，所以不触发 customRef 的 trigger 去更新副作用，同样也涉及字符串长度不变，单独改某一个字母的时的 大写转小写修饰符，https://github.com/vuejs/core/issues/10254有一个类似的issues，yyx认为是预期的行为，状态方面没有任何变化，因此不会发生任何更新。并认为涉及性能，所以不会更改。

他给出解决办法是 1 是先把没有 trim 的值付给动态值，让 haschange 判断为 true 触发后续，然后在修饰符操作后在赋值一次，触发 trigger，并且由于 vue 做了去重，所以不会重复操作两次 dom，2 是通过 watch 控制

还有既然是 customRef 那就可以自己在 setter 函数里手动直接触发一次 trigger 副作用，或者 forceUpdate 一下

那为什么 v-model 自带的 trim 不会导致这个问题呢？


他的 v-model 绑定的时候再监听了一个 change 事件去修改元素的值
